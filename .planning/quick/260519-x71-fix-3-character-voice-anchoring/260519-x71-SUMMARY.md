# Fix 3 — Character voice anchoring

Status: code landed, **awaiting human verify** (Task 3 is a `checkpoint:human-verify` gate).

## What changed

1. **`Friend` type** (`src/lib/friends.ts`) — three new optional fields:
   - `mesExample?: string[]` — 2-3 in-voice one-liners, ≤80 chars each.
   - `antiPatterns?: string[]` — 2-3 "never do this" rules.
   - `stances?: Record<string, string>` — topic → short opinion (≤120 chars).

2. **`buildVoiceAnchorBlock(friend, userMessage)`** (`src/lib/orchestrator.ts`)
   assembles up to three labelled lines:
   - `[How you talk: ex1 | ex2 | ex3]`
   - `[What you never do: rule1 | rule2]`
   - `[What you believe: topic: position | topic: position]`

   Empty / missing field → that line is omitted (no `[How you talk: ]` artifacts).
   When nothing emits, returns `""`. Stances are filtered to the top 1–2 by
   relevance to the latest user message.

3. **U-shape injection** in the per-character prompt builder (around line 992):
   - Voice block prepended BEFORE the Fix 2 memory prepend, so the final top-down
     order is `[memory] → [voice] → base prompt`.
   - `mesExample` line duplicated at the END of the prompt (U-shape bottom
     anchor), guarded on a non-empty array.

4. **13 core characters seeded** in `src/lib/friends.ts`. All extractions are
   mechanical — every value traces back to a phrase already in the
   character's `systemPrompt` prose.

## Deviations from plan

1. **Rule 1 (correctness fix to a primitive)** — the plan specified
   "filter stances where `computeTopicAffinity > 0`". That predicate does not
   match the function's actual behavior:
   - `computeTopicAffinity` returns `0.5` as a neutral floor when the user
     message contains no recognized keywords. Strict `> 0` would always pass
     and stances would never be omitted.
   - The function normalizes by `overlap / matchedTags.size`. A single-tag
     stance scores ≤0.5 whenever the user message spans more than one topic
     bucket.

   The implementation defines a local `scoreStanceRelevance(topic, userMessage)`
   that probes for the neutral-floor case, uses raw affinity when matched tags
   exist, and falls back to a verbatim substring check for stance topics that
   are content words but not in the dictionary (e.g. "marriage"). Documented in
   the source comment.
